# ฝึกสนทนา

เมนูฝึกสนทนาอยู่แทน Battle ในกริดหน้าแรก ส่วน Battle เข้าผ่านปุ่มกลางด้านล่างตามเดิม

## ติดตั้งบน Supabase

1. รัน `supabase/migrations/202611080001_conversation_lessons.sql` ตามด้วย `supabase/migrations/202611080002_conversation_costs.sql` ใน SQL Editor ของโปรเจกต์เดียวกับแอป หรือใช้ migration workflow เดิม หลังตรวจสอบรายการ pending migrations แล้ว หากติดตั้ง migration แรกแล้วให้รันเฉพาะไฟล์ที่สอง
2. ใช้ `OPENAI_API_KEY` ฝั่ง Edge Function ตัวเดียวกับ Books ห้ามใส่ key ในตัวแปร `VITE_*`
3. หลัง `supabase login` ให้ deploy เฉพาะฟังก์ชันใหม่:

```powershell
supabase functions deploy generate-conversation --project-ref koagashnqnjbpetddbor
```

กำหนดโมเดลผ่าน secret `CONVERSATION_TEXT_MODEL` ได้ ถ้าไม่ได้ตั้งจะใช้ `OPENAI_TEXT_MODEL` แล้วจึง fallback เป็นโมเดลเดียวกับแบบทดสอบหนังสือเดิม

## ค่าใช้จ่ายต่อชุดบทเรียน

การ์ดคลังกลางและหน้ารายละเอียดแสดงต้นทุนสะสมโดยประมาณทั้ง THB/USD พร้อมแยกค่าตรวจหัวข้อและค่าสร้างเนื้อหา เก็บ token usage, โมเดล, อัตราราคา, เวอร์ชันราคา และอัตราแลกเปลี่ยนต่อการเรียก API ใน `conversation_generation_runs` ซึ่งอ่าน/เขียนได้เฉพาะ backend ส่วนยอดรวมบนบทเรียนอ่านได้ทุกบัญชีที่เข้าสู่ระบบ

คำนวณ input ปกติและ cached input แยกกัน ใช้ `USD_THB_RATE` ณ เวลาที่เรียก API ยอดรวมสะสมจากแต่ละรายการจึงไม่เปลี่ยนย้อนหลังเมื่อปรับอัตราใหม่ การลองสร้างใหม่รวมต้นทุนเดิม และบันทึก usage ก่อนตรวจโครงสร้างเพื่อไม่ตกหล่นเมื่อ AI ส่งเนื้อหาไม่ผ่าน validation การตรวจหัวข้อซ้ำหลายรอบระหว่างจองงานถูกรวมไว้ด้วย การเข้าเรียนปกติไม่เรียก AI เพิ่ม แต่การพิมพ์หัวข้อใหม่ที่มีความหมายตรงกับชุดเดิมอาจมีค่าตรวจความหมายเพิ่มให้ชุดนั้น หัวข้อที่ปฏิเสธ/ยังไม่ได้ผูกกับชุดใดเก็บ log แยกไว้ ไม่เพิ่มยอดให้บทเรียนอื่น

ราคาเริ่มต้นเป็นค่าประมาณจาก config Books เดิมของโปรเจกต์ ไม่ใช่ราคาสดหรือใบแจ้งหนี้ ตั้ง `CONVERSATION_INPUT_USD_PER_M`, `CONVERSATION_CACHED_INPUT_USD_PER_M`, `CONVERSATION_OUTPUT_USD_PER_M` ให้ครบทั้งสามค่าเพื่อ override และใช้ `CONVERSATION_PRICING_VERSION` ระบุเวอร์ชัน ดูตัวอย่างใน `supabase/functions/generate-conversation/.env.example`

บทเรียนเก่าที่ไม่มี log และโมเดลที่ไม่มีราคาจะไม่แสดงเป็นศูนย์ หาก API ขัดข้องโดยไม่ส่ง usage กลับมา จะยังไม่สามารถระบุค่าเรียกครั้งนั้นได้ ยอดแสดงครอบคลุมรายการ usage ที่บันทึกได้เท่านั้น ไม่รวม Supabase/hosting

การ deploy หน้าเว็บใช้ workflow เดิมของโปรเจกต์ การ build frontend อย่างเดียวไม่ได้ติดตั้งตารางหรือ Edge Function

## พฤติกรรม

- ทุกบัญชีที่เข้าสู่ระบบอ่านคลังกลางได้ ไม่มีการเปิดบทเรียนให้ผู้ที่ยังไม่เข้าสู่ระบบ
- หัวข้อสำเร็จรูป 6 แบบหรือพิมพ์หัวข้อเอง 2–200 ตัวอักษร เลือกได้ 3 ระดับ
- แต่ละชุดมี 3 บท แต่ละบทสอน 4–6 คำและ 1–2 รูปประโยค ตามด้วย 8–12 แบบฝึก
- แบบฝึกมีเลือกตอบ เรียงคำ/กลุ่มคำ ฟังแล้วเลือก และเลือกคำตอบโต้ ไม่มีภาพหรือไมโครโฟน
- เสียงใช้ speech synthesis ของเบราว์เซอร์เดิม คุณภาพ/เสียงจีนที่มีขึ้นกับอุปกรณ์ ควรทดสอบบนมือถือจริงด้วย
- คำตอบตรวจบนฐานข้อมูล เก็บคำตอบล่าสุด จำนวนครั้งที่ตอบ และสถานะจบบทแยกผู้ใช้ บันทึกทีละข้อแบบ atomic จึงไม่เขียนทับคำตอบข้ออื่นเมื่อเปิดหลายแท็บ
- กลับมาเรียนต่อจากข้อที่ยังไม่ตอบได้ ข้อที่ตอบผิดเข้าทบทวนได้ เรียนจบกับตอบถูกครบเป็นคนละสถานะ
- ชุดบทเรียนที่สร้างแล้วไม่ถูกสร้างใหม่ทุกครั้งที่เรียน การลองใหม่ของชุดที่ล้มเหลวใช้แถวเดิม

## การป้องกันซ้ำ

1. Normalize หัวข้อและค้นหา alias ก่อนเรียก AI หัวข้อเดิมที่เคยจับคู่จึงไม่ต้องใช้ AI ตรวจซ้ำ
2. หัวข้อใหม่ส่งชื่อ เป้าหมาย และระดับของบทเรียนในคลังให้ AI ตรวจความหมาย ใช้ชุดเดิมเมื่อสถานการณ์และเป้าหมายตรงกัน และแยกระดับภาษาต่างกัน
3. RPC ใช้ transaction advisory lock และ unique constraints เพื่อจองชุดเดียวต่อ canonical title/ระดับ และสร้าง alias ให้ชื่อที่ต่างกัน
4. ถ้ามีชุดใหม่เพิ่มระหว่างตรวจความหมายกับจองงาน RPC ปฏิเสธ snapshot เก่า ให้ฟังก์ชันอ่านคลังและเทียบใหม่ก่อนสร้าง จึงครอบคลุมคำขอชื่อใกล้เคียงที่เข้ามาพร้อมกัน
5. การสร้างทำเบื้องหลัง หน้าเว็บติดตามทุก 5 วินาที งานที่ขาดการตอบกลับเกิน 10 นาทีลองใหม่ได้ โดย token ประจำงานกันผลจากงานเก่าเขียนทับงานใหม่

ความตรงกันของความหมายยังขึ้นกับ AI ไม่ใช่การรับประกันว่าเนื้อหาที่ใกล้กันจะไม่ซ้ำเลย ส่วนชื่อที่ normalize ตรงกันและการจองงานพร้อมกันมีข้อบังคับใน DB เมื่อคลังใหญ่มากควรเพิ่ม semantic index แทนการส่ง metadata ทั้งคลังเพื่อจำกัดเวลาและค่าใช้จ่าย

## สิทธิ์ข้อมูล

- `conversation_courses`: authenticated อ่านได้ แก้ไขได้เฉพาะ backend/service role
- `conversation_topic_aliases`: backend เท่านั้น
- `conversation_progress`: authenticated อ่านได้เฉพาะบัญชีตนเอง เขียนผ่าน RPC ซึ่งใช้ `auth.uid()` ไม่รับรหัสผู้ใช้จาก client
- ไม่มีการเพิ่มเหรียญหรือรางวัลเกมจากบทเรียนนี้

npm.cmd test

```powershell

node scripts/test-conversation-db.mjs
```

ชุดทดสอบ DB ครอบคลุม reservation, canonical aliases, semantic reuse ตาม course ID, catalog snapshot, การแยกระดับ, retry token, RLS สองบัญชี, การตรวจคำตอบ และการรวมผลทีละข้อ โดยจำลอง schema `auth` ของ Supabase ไม่ได้เรียก OpenAI จริง

ก่อนเปิดใช้งานจริงให้ลองสร้างชุดหนึ่งบน staging และตรวจภาษาจีน/พินอิน/คำแปล/ตัวลวงด้วย การตรวจโครงสร้างอัตโนมัติไม่สามารถรับรองความถูกต้องทางภาษาของทุกโจทย์ได้
